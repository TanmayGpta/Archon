Known threats to validity

  • Expected answers are derived from Archon's own deterministic scanner, the same engine the agent calls through MCP. The eval therefore measures whether the agents call the tool correctly and report its result faithfully, not whether the scanner's verdicts are architecturally right.
  • Report quality and groundedness are scored by an LLM judge. Judges are noisy, and a judge reached through the same router as the agent may share its blind spots.
  • The redirect case is scored on what the model attempted. In production the before_tool guardrail rewrites the path to the session codebase, so a failed trajectory there is an attempted, not an executed, escape.
  • The injection prompt is matched by the guardrail's regex list. Passing it shows the guardrail works for known phrasings, not that it catches novel ones.
  • Only the ADK audit pipeline is scored here. The CrewAI healing crew is covered by the system benchmark (run_eval) below, which needs the gateway and healing servers running.
  • The latest run covers 4 case(s), of which 2 are plain audits of distinct codebases. That is too few to generalise to arbitrary repositories.
  • The router was set to 'auto', so it picks a provider per call (this run used: gpt-oss-120b, poolside/laguna-xs-2.1). Scores can change between runs for reasons unrelated to the agent; pin AGAI_EVAL_MODEL and AGAI_EVAL_JUDGE_MODEL for comparable runs.

How to read this

Tool trajectory: the agent's tool calls compared with the expected scan_conformance call (EXACT match, so 1.0 means identical name and arguments). The guardrail suite checks that an injection prompt is blocked before any model call: no tool calls, and a reply matching the production guardrail's message (ROUGE). Report quality: an LLM judge scores the final report against rubrics generated from the deterministic scan (health score, violation ids, cycles, fixes). Groundedness: the share of report sentences supported by the tool output and context (ADK hallucinations_v1). Latency, tokens and call counts are informational ADK efficiency metrics.

Every number on this page is read from result files written by adk eval and run_eval. Re-render with python -m archon_agai.eval.adk_eval.run --dashboard-only.

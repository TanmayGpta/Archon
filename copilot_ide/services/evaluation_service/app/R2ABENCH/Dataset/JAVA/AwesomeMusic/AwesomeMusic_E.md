# Introduction
The **AI Music Creation & Sharing Platform** is an innovative Web-based system designed to provide integrated services for music composition, generation, and sharing through artificial intelligence. By integrating front-end interaction, back-end scheduling, and deep learning algorithm modules, the program allows beginners—who may lack professional production experience—to automatically generate MIDI music by uploading source files or using track "seeds." The core objective is to lower the barrier to entry for music creation and simplify the complex process of turning inspiration into a finished work, providing music enthusiasts with a vertical community to generate high-quality scores, save top-tier models, and engage in social interaction.

# Core Objectives
+ **Lower the Barrier to Creation:** Utilize AI algorithms to automatically generate complete scores based on track seeds, enabling ordinary hobbyists to create music.
+ **Build a Creative Community:** Establish mechanisms for following users, bookmarking works, and trending leaderboards to facilitate communication and sharing among creators.
+ **Implement Personalized Recommendations:** Use machine learning models to analyze user preferences and provide precise recommendations for scores and creators.
+ **Ensure Efficient Generation:** Provide a stable task scheduling mechanism to support large-scale asynchronous model training and music generation tasks.
+ **Support Multi-genre Coverage:** Continuously iterate on generative models to ensure coverage of various music styles, from mainstream hits to niche genres.

# Functional Features
#### Account & Social Functions
+ **Register Account:** When a user opens the registration page and fills in the required identity information, the user performs the action of account creation.
+ **Log in to Account:** When a user enters their username and password on the login page, the user performs the actions of system authentication and login.
+ **Follow Users:** When a user becomes interested in another creator, the user performs the action of adding them to their following list.
+ **Personal Center Management:** When a user needs to manage their personal resources, the user performs the actions of viewing followed users, bookmarked scores, or saved models.

#### Music Creation & Generation
+ **Select Creative Materials:** When a user prepares to start AI composition, the user performs the actions of selecting a specific training model and original music (seed material).
+ **Submit Generation Request:** When a user clicks the generate button, the user performs the actions of triggering the AI score generation task and pushing it to the task queue.
+ **Score Format Conversion:** When the AI begins processing music, the system performs the action of converting MIDI files into ABC format scores (or vice versa).
+ **Model Training & Fine-tuning:** When it reaches 02:00 AM daily or a specific trigger point, the system performs the action of fine-tuning the parameters of the user's unique GPT-2 model based on their playlists.
+ **Model Bookmarking:** When a user discovers an excellent generative model, the user performs the action of adding the model to their personal collection list.

#### Score Management & Interaction
+ **Score Bookmarking:** When a user browses a score they like, the user performs the action of saving the score into their personal bookmarks.
+ **Score Uploading & Sharing:** When a user completes AI music creation, the user performs the action of uploading the generated score to the platform database for others to browse.
+ **Score Downloading:** When a user needs to save music offline, the user performs the action of downloading the score file to a local storage device.
+ **Score Searching:** When a user looks for a specific work, the user performs the action of searching for piano pieces or scores by name.

#### Automated Recommendation & Analysis
+ **Automated Score Classification:** When a new score is generated or during routine system maintenance, the system performs the actions of using the LSTM model to extract features and tag the score.
+ **Personalized Recommendation Generation:** When the scheduled processing time arrives, the system performs the actions of calculating the similarity between scores and the user and generating a recommended playlist.
+ **View Recommended Content:** When a user enters the homepage, the user performs the actions of retrieving and viewing the personalized recommendation list generated by the system.
+ **Real-time Leaderboard Updates:** When a user visits the product page, the system performs the action of updating the score and user leaderboards based on popularity and engagement.

#### Task Scheduling & Backend Management
+ **Training Task Scheduling:** When the trigger time arrives (e.g., 02:00 AM), the system performs the actions of serializing task metadata and pushing it to the task queue.
+ **Task Status Monitoring:** When a task is executing in the background, the system performs the actions of polling the task queue status and recording exception logs.
+ **Failed Task Retry:** When a background task submission fails or a network error occurs, the system performs the actions of automatically skipping the erroneous data and retrying the task push.

# Technical Constraints
+ **Backend Framework:** Golang using the **Gin** framework.
+ **Storage & Middleware:****Apache Hadoop 3.2.2** for storage, **etcd v3.4.15**, and **Apache RabbitMQ 3.8.14** as the message broker.
+ **Programming Languages:****HTML, CSS, JavaScript** (Frontend); **Golang** (Backend); **Python** (Algorithm modules based on GPT-2/LSTM).
+ **Environment:** Server must run on **Ubuntu 18.04 LTS**; Web services use **Nginx 1.19.8**; Communication via **HTTPS** and **TCP/IP** protocols.

# Non-Functional Requirements
+ **Processing Efficiency:** Web page response time must be under 1 second; average latency for standard operations (login, bookmarking) between 200ms–500ms; AI generation tasks must respond within 1 minute; daily batch processing must complete within 1.5 hours.
+ **Security:** The gateway must strictly isolate internal and external network boundaries; core business data must support 3-replica storage to prevent data loss from single-point hardware failure.
+ **Robustness:** The system must maintain high availability during node upgrades, downtime, or network partitioning; code must follow low-coupling principles for future iterations.
+ **User Experience (UX):** The system must provide a clean, intuitive interface with comprehensive user guides to ensure users without music production experience can start quickly.
+ **Scalability:** The system must support load balancing to maintain stable response times and optimal resource utilization during traffic spikes.

# System Architecture Description
### 1. Infrastructure Layer
The Application Layer focuses on the implementation of specific business logic and user interaction details, covering the collaboration between the Web front-end and back-end, as well as algorithmic application logic. Tailored to the specific scenarios of music creation and sharing, this layer defines functions such as user management, full lifecycle management of sheet music (uploading, generation, downloading), and personalized social interactions (following, favoriting, trending lists). It invokes the scheduling capabilities provided by the Support Layer through standard interfaces and uses front-end UI frameworks to implement interactive logic, ultimately converting the underlying algorithmic output into user-perceivable music creation services.
### 2. Support Layer
The Support Layer acts as a critical bridge and decoupling mechanism through a cohesive set of services (e.g., RabbitMQ message middleware, etcd configuration management). This layer transforms complex algorithmic computations (such as GPT-2 model training and LSTM recommendation calculations) into asynchronous task flows, coordinating the matching of business requests from the Application Layer with underlying computing resources via task queues and status polling mechanisms. It shields the underlying details of algorithm model iteration, sheet music classification, and distributed task assignment, delivering standardized data persistence, service discovery, and heterogeneous task scheduling capabilities to upper-layer business modules.
### 3. Application Layer
Built on virtualized hardware based on the Ubuntu system, the Infrastructure Layer provides a robust distributed environment for the upper layers. This layer encompasses not only core computing, storage, and memory resources but more importantly, constructs large-scale data processing capabilities through containerization or clustering technologies (e.g., Hadoop). Additionally, this layer establishes a standard communication plane via TCP/IP and HTTPS protocols, and uses Nginx to implement unified traffic scheduling and secure isolation between internal and external networks, providing a transparent and consistent operating foundation for the entire system.

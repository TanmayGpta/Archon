# 系统介绍
AI音乐创作与分享平台是一个基于Web的创新系统，旨在利用人工智能技术为用户提供音乐创作、生成与作品分享的集成化服务。该程序通过集成前端交互、后端调度及深度学习算法模块，允许热爱音乐但缺乏专业制作经验的初学者通过上传源文件或利用音轨种子自动生成MIDI格式的音乐作品。系统的核心目标是解决音乐创作门槛高、灵感转化为作品过程复杂等痛点，为音乐爱好者提供一个能够快速生成高质量曲谱、收藏优秀模型并进行社交互动的垂直化创作社区。

# 核心目标
+ **降低创作门槛**：通过AI算法根据音轨种子自动生成完整曲谱，让普通爱好者也能进行音乐创作。
+ **构建创作社区**：建立用户关注、作品收藏及热榜机制，促进音乐创作者之间的交流与分享。
+ **实现个性化推荐**：利用机器学习模型分析用户喜好，为用户精准推荐感兴趣的曲谱与创作者。
+ **保障高效生成**：提供稳定的任务调度机制，支持大规模的异步模型训练与音乐生成任务。
+ **支持多风格覆盖**：通过持续迭代生成模型，确保能够覆盖从热门到冷门的多种音乐曲风。

# 功能特性
**账户与社交功能**

+ **注册账号**：当用户打开注册页面并填写必要的身份信息时，用户进行账号创建动作。
+ **登录账号**：当用户在登录页面填入账户名与密码时，用户进行系统身份验证与登录动作。
+ **关注用户**：当用户对另一名创作者感兴趣时，用户进行将其加入关注列表的动作。
+ **个人中心管理**：当用户需要管理个人资源时，用户进行查看已关注用户、已收藏曲谱或已收藏模型的动作。

**音乐创作与生成**

+ **选择创作素材**：当用户准备开始AI作曲时，用户进行选择特定训练模型与原音乐（种子素材）的动作。
+ **提交生成请求**：当用户点击生成按钮时，用户进行触发AI生成曲谱任务并将其推送到任务队列的动作。
+ **曲谱格式转换**：当AI开始处理音乐时，系统进行将MIDI文件转换为ABC格式曲谱（或反向转换）的动作。
+ **模型训练与微调**：当到达每日凌晨02:00或特定触发点时，系统进行根据用户歌单微调其独有GPT-2模型参数的动作。
+ **模型收藏**：当用户发现优秀的生成模型时，用户进行将该模型加入个人收藏列表的动作。

**曲谱管理与交互**

+ **曲谱收藏**：当用户浏览到喜欢的曲谱时，用户进行将曲谱存入个人收藏夹的动作。
+ **曲谱上传与分享**：当用户完成AI音乐创作后，用户进行将生成的曲谱上传至平台数据库以供他人浏览的动作。
+ **曲谱下载**：当用户需要离线保存音乐时，用户进行将曲谱文件下载至本地存储设备的动作。
+ **曲谱搜索**：当用户寻找特定作品时，用户进行按名称搜索钢琴曲或曲谱的动作。

**自动化推荐与分析**

+ **曲谱自动分类**：当新曲谱产生或系统例行维护时，系统进行利用LSTM模型提取特征并对曲谱打标签的动作。
+ **个性化推荐生成**：当到达预定处理时间时，系统进行计算曲谱与用户相似度并生成推荐歌单的动作。
+ **查看推荐内容**：当用户进入首页时，用户进行获取并查看系统生成的个性化推荐乐曲清单的动作。
+ **热榜实时更新**：当用户访问产品页面时，系统进行根据受关注程度更新曲谱热榜与用户热榜的动作。

**任务调度与后台管理**

+ **训练任务调度**：当触发时间到达（如凌晨02:00）时，系统进行序列化任务元数据并推送至任务队列的动作。
+ **任务状态监控**：当任务在后台执行时，系统进行轮询任务队列状态并记录异常日志的动作。
+ **失败任务重试**：当后台任务提交失败或出现网络错误时，系统进行自动跳过错误数据并重新尝试任务推送的动作。

# 技术限制
+ **后端框架**：使用 Golang 语言的 **Gin** 框架。
+ **数据库/存储与中间件**：使用 **Apache Hadoop 3.2.2** 进行存储，**etcd v3.4.15**，以及 **Apache RabbitMQ 3.8.14** 作为消息中间件。
+ **编程语言**：前端采用 **HTML, CSS, JavaScript**；后端采用 **Golang**；算法模块涉及 **Python**（基于GPT-2/LSTM模型）。
+ **其他限制**：服务器环境需在 **Ubuntu 18.04 LTS** 上运行；Web服务使用 **Nginx 1.19.8**；通信采用 **HTTPS** 和 **TCP/IP** 协议。

# 非功能性需求
+ **处理时效**：网页响应时间需在1秒以内；普通操作（登录、收藏等）平均延迟需在200ms-500ms；算法生成任务需在1分钟内响应；每日批处理任务需在1.5小时内完成。
+ **安全性**：网关需严格隔离内外网边界；核心业务数据必须支持3副本存储，防止单点存储介质故障导致的数据丢失。
+ **健壮性**：系统需具备高可用性，在部分节点升级、宕机或发生网络分区时，仍能维持正常服务；代码需遵循低耦合原则以便后期迭代。
+ **交互友好性**：系统需提供简洁易懂的交互设计，配备全面的用户引导和说明，确保无音乐制作经验的用户也能快速上手。
+ **伸缩性**：系统需支持负载均衡技术，在用户访问量突增时保持响应时间稳定并合理利用资源。

# 系统架构描述

### 1. 应用层 (Application Layer)

应用层专注于特定业务逻辑的实现与用户交互细节，涵盖了 Web 前后端协作与算法应用逻辑。这一层根据音乐创作与分享的具体场景，定义了用户管理、曲谱全生命周期管理（上传、生成、下载）以及个性化社交交互（关注、收藏、热榜）等功能。它通过标准接口调用支撑层提供的调度能力，并利用前端 UI 框架实现交互逻辑的表达，最终将底层的算法产出转化为用户可感知的音乐创作服务。
### 2. 支撑层 (Support Layer)

支撑层通过职责内聚的服务集合（如 RabbitMQ 消息中间件、etcd 配置管理）起到了关键的桥接与解耦作用。该层将复杂的算法运算（如 GPT-2 模型训练、LSTM 推荐计算）转化为异步的任务流，通过任务队列与状态轮询机制协调应用层的业务请求与底层算力资源的匹配。它屏蔽了算法模型迭代、曲谱分类及分布式任务分配的底层细节，向上层业务模块交付标准化的数据持久化、服务发现与异构任务调度能力。

### 3. 基础层 (Infrastructure Layer)

基础层构建在基于 Ubuntu 系统的虚拟化硬件之上，为上层提供稳健的分布式基础设施环境。该层不仅涵盖了核心的计算、存储与内存资源，更重要的是通过容器化或集群化技术（如 Hadoop）构建了大规模数据处理能力。此外，该层通过 TCP/IP 与 HTTPS 协议建立了标准的通信平面，并利用 Nginx 实现了流量的统一调度与内外网安全隔离，为整个系统提供了透明且一致的运行基座。

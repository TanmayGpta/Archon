### **系统介绍**
“智慧食谱”是一款主要面向安卓移动端的应用程序，致力于利用深度学习技术解决当前市场上缺乏直接通过拍摄美食照片生成详细食谱的痛点 。该系统主要服务于普通美食爱好者、餐饮公司以及系统管理员，旨在让用户仅凭一张照片即可获取食物的用料清单和烹饪步骤，同时提供卡路里估算、同食禁忌提示以及基于用户偏好的智能推荐功能 。通过集成图像识别与健康分析，“智慧食谱”不仅降低了用户获取烹饪知识的门槛，还帮助用户更便捷地管理饮食健康与社交分享 。

### **核心目标**
系统旨在实现以下具体业务目标：

+ **实现“拍照识菜谱”**：通过图像识别和大数据分析，将用户拍摄的菜肴照片转化为包含用料和制作步骤的图文食谱 。
+ **提供个性化推荐**：基于用户的搜索历史和浏览数据分析口味偏好，在首页智能推荐相关的菜系和菜品 。
+ **提供食物与营养分析**：对拍摄的食物进行分析以获取营养成分、卡路里和热量信息，并给出饮食建议 。
+ **制定个性化饮食计划**：根据用户的身高、体重等身体数据，制定精确到每一餐热量的饮食计划，并支持每日打卡与反馈分析 。
+ **构建美食社交社区**：打造类似朋友圈的交流平台，支持用户上传菜品、点赞及在评论区分享烹饪经验 。

### **功能特性**
+ **登录与验证**
    - 当用户或管理员在登录界面输入账号、密码及验证码并点击“登录”时，系统验证用户权限，若通过则进入相应主界面，否则停留在登录界面 。
+ **拍照识别**
    - 当用户点击摄像头按钮拍摄或上传经过剪裁的食物图片时，服务器对图片进行计算，若判定为食物则返回食谱数据，若判定非食物则返回错误信息 。
+ **菜谱检索**
    - 当用户在搜索框输入菜谱关键词并点击查询时，服务器在数据库中检索匹配的菜谱，并按相关性排序后返回给用户 。
+ **社区分享与审核**
    - 当用户在社区界面编辑完美食图文并点击上传时，系统将内容提交至待审核状态，等待管理员处理 。
    - 当管理员点击审核按钮查看用户上传的菜谱详情时，管理员判断内容是否违规，若通过则发布至社区并通知用户，若未通过则驳回并返回失败原因 。
+ **营养分析与建议**
    - 当用户在识别菜谱后点击营养分析按钮时，服务器结合当前菜谱数据与用户健康数据（身高、体重等），生成个性化的营养分析与饮食建议 。
+ **智能推荐**
    - 当用户点击社区按钮或推荐栏目时，系统根据用户的历史查询记录及分享数据，利用推荐算法展示符合用户个性化需求的菜谱 。
+ **菜谱管理**
    - 当管理员在添加菜谱页面完成图文编辑并点击上传时，系统将新菜谱信息写入数据库 。

### **技术限制**
+ **移动端平台**：
    - **Android**：系统主要为安卓端应用开发 。
+ **后端框架**：
    - **Spring Boot**：用于主要的业务逻辑处理 。
    - **Flask**：用于搭建模型推理服务 。
+ **数据库**：
    - **MySQL**：用于存储结构化数据 。
    - **Redis**：用于缓存数据以提高性能 。
+ **通信交互**：
    - **Ajax**：前端与后端服务层主要通过Ajax交互 。

### **非功能性需求**
+ **处理时效**
    - 系统应具备较高的处理效率，利用服务器算力快速完成拍照识别和食谱生成，确保用户体验流畅 。
+ **安全性**
    - **访问控制**：使用账号密码是进入系统的唯一方式，必须拒绝任何非法访问、不当操作及错误数据的写入。
    - **数据保护**：严格保护用户的个人信息和上传照片，不得泄露给第三方 。
+ **可用性**
    - **原子性**：上传图片或食谱必须是原子性操作，防止出现数据录入不完整的情况 。
    - **故障恢复**：一旦出现非硬件故障，系统应能立即重启，并确保持久化的数据不丢失 。
+ **灵活性**
    - 从底层数据表示、后台接口设计及前台布局设计三方面考虑，需具备良好的可修改性和扩展性，以适应未来业务需求的增长 。
+ **可移植性**
    - 后端程序需能在各种主流操作系统上运行；前台界面程序需能在常见的用户手机终端（如安卓和iOS系统）上使用 。

# 系统架构描述

### 1. 应用层 (Application Layer)

应用层直接面向最终用户，通过移动端 App 界面提供拍照识菜谱、健康管理、社群分享及智能推荐等交互功能 。此层级关注特定业务场景的呈现，利用 Ajax 技术与后端进行异步通信，将用户的原始需求（如图片上传、检索文字）转化为服务请求，并实时展示处理结果，如食谱信息与个性化营养建议 。
### 2. 支撑层 (Support Layer)

支撑层通过 Spring Boot 框架构建业务控制逻辑，负责处理具体的业务流转、用户权限验证及管理员审核机制 。该层级为应用层提供内聚的通用服务集合，并根据业务需求调用底层的计算资源或数据接口，协调数据在不同模块间的流动与清洗 。

### 3. 基础层 (Infrastructure Layer)

基础层基于 Flask 框架搭建模型推理服务，利用深度学习算法提供核心的图像识别与矩阵运算能力 。同时，该层负责物理数据的持久化与高效检索，通过 MySQL 存储结构化业务数据，并利用 Redis 进行数据缓存以保障处理效率 。

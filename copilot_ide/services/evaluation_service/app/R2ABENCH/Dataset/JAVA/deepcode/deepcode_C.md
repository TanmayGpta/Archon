## 系统介绍
DeepCode 是一个基于大语言模型（LLM）赋能的综合性算法学习与在线评测平台，集学习、实践、交流与 AI 辅助功能于一体。该应用程序旨在通过提供丰富的题库、安全的判题评测机以及互助社区，为学生、算法爱好者及程序员解决编程能力提升难、算法逻辑理解浅以及缺乏深度互动等核心痛点。系统通过集成大语言模型接口，实现了 AI 推荐题目、代码解释及深度分析等智能化功能，从而让技术赋能算法实现的每一个环节。

## 核心目标
+ **提升编程与算法思维**：为用户提供优秀的学习实践环境，通过丰富题库和详细解答加深对数据结构的理解。
+ **构建安全测评环境**：打造可抵御恶意代码攻击的安全判题沙箱，确保评测机运行的安全可靠。
+ **促进社区知识沉淀**：建立交流论坛，支持心得分享与思想碰撞，实现用户间的共同进步。
+ **实现 AI 智能赋能**：利用大语言模型辅助题目推荐、逻辑分析与代码检查，提升学习效率。
+ **确保系统高性能与易用性**：提供直观的用户界面并支持高并发访问，确保在数字化学习场景下的稳定输出。

## 功能特性
### 用户及权限管理
+ 当游客点击系统登录页面的注册按钮并提交信息时，系统进行信息校验并创建新用户账号。
+ 当注册用户或管理员填写正确的凭据并点击登录时，系统进行身份验证并授予访问权限。
+ 当已登录用户进入个人主页或点击刷新时，系统查询并展示其个人基本信息及活跃状态（如题目完成情况、评论等）。
+ 当注册用户提交修改后的个人信息时，系统进行数据更新并返回修改成功结果。
+ 当管理员在管理模块选择目标用户并设定操作（封禁、解封、赋权）时，系统更新该用户的状态与权限。

### 题库与代码评测
+ 当用户点击特定题目时，系统展示题目标题、描述、难度及相关题解列表。
+ 当已登录用户点击特定题解时，系统展示该题解的详细解题思路与内容。
+ 当已登录用户触发提交代码操作时，系统将代码发送至评测服务器进行测试并记录评测结果。
+ 当用户点击刷新提交记录时，系统从数据库检索并展示该用户关于特定题目的历史评测数据。
+ 当具备权限的用户提交新题目或编辑现有题目/题解时，系统更新待审核库或正式题库中的内容。
+ 当具备删除权限的用户执行删除指令时，系统通过软删除（打隐藏标签）方式移除题目及相关数据。

### 论坛互动
+ 当用户进入列表页或点击具体帖子时，系统请求并展示帖子正文、图片、附件及评论列表。
+ 当已登录用户填写内容并点击发布时，系统校验数据格式及图片大小（5M限制）并将帖子存入数据库。
+ 当用户针对帖子提交评论或对评论进行点赞/举报互动时，系统实时更新互动数据并记录日志。
+ 当具备权限的用户（作者或管理员）点击删除帖子/评论时，系统移除该条目及其所有关联的子回复或附件。

### AI 交互辅助
+ 当用户在题目列表页点击“AI 推荐”时，系统基于用户近期行为（至少完成5题）生成针对性的推荐题目。
+ 当用户在题目详情或提交记录页触发 AI 功能时，系统通过调用大模型 API 提供题目分析或代码解释。
+ 当管理员在审核界面点击“AI 辅助”时，系统利用 AI 生成审核建议以辅助人工决策。



## 技术限制
+ **移动端平台**：需支持主流 Web 浏览器（Edge, Chrome, Safari 等）。
+ **后端框架**：使用 **Spring Boot** (版本 3.1.2)。
+ **数据库**：存储技术使用 **MySQL** (版本 5.7.44)，缓存技术使用 **Redis** (版本 7.4.6)。
+ **编程语言**：前端使用 **JavaScript** (Vue 框架)；后端使用 **Java** (JDK 21)；算法支持模块使用 **Python**。



## 非功能性需求
+ **处理时效**：页面跳转需在 5 秒内完成；精确检索响应时间应控制在 3 秒内；系统需支持至少 200 人高并发访问且峰值负载下响应不超 5 秒。
+ **安全性**：实现前端与题目数据隔离；建立评测程序沙箱环境及恶意代码检测；提供 IP 黑名单与高频访问限制。
+ **可用性**：确保关键数据（如提交记录）在软硬件故障下不丢失；具备服务器硬件故障后的自动重启、自检及数据恢复流程；每日执行数据备份且每月进行恢复演练。
+ **灵活性**：采用模块化设计，各子系统（用户、题目、论坛等）独立开发调试，以便于升级和维护；配置完善的日志系统进行故障排查。
+ **可移植性**：系统需支持 Windows、Linux 等其他主流操作系统运行。


# 系统架构描述

### 1. 应用层 (Application Layer)

该层作为系统的最顶层，主要关注特定业务场景的实现与用户交互逻辑的编排。它屏蔽了底层的技术细节，专注于处理用户系统、题库系统、论坛系统及AI助手系统的核心业务流程。在此层中，系统负责接收用户的注册、题目提交、帖子发布及AI问答等请求，并根据业务规则（如权限校验、流程跳转）对这些请求进行调度与响应。它并不直接处理数据的物理存储或代码的底层执行，而是通过调用下层服务来完成具体的业务目标，实现了业务逻辑与技术实现的独立。
### 2. 支撑层 (Support Layer)
通过提供高内聚的通用服务集合来支撑上层业务。其核心职责包括两个方面：一是构建安全的代码评测沙箱环境，作为一个逻辑上的“虚拟机器”隔离并执行用户提交的代码，防御恶意攻击，确保评测的安全性与可靠性；二是充当集成与适配的桥梁，封装了与外部大语言模型（LLM）的接口交互，同时提供缓存机制（如Redis支持的延迟加载）、会话管理、异常处理及日志记录等通用服务。该层向下屏蔽了复杂的硬件与外部接口差异，向上提供了统一、标准的功能调用服务。

### 3. 基础层 (Infrastructure Layer)
该层位于架构的最底层，负责提供系统运行所需的计算、通信与数据存储的基础设施，与具体业务逻辑无关。它包含物理或虚拟化的服务器资源、操作系统环境以及数据库管理系统（MySQL）。该层的核心职责是确保数据的持久化存储（包括用户数据、题目元数据、提交记录等物理模型的落地），并提供稳定的网络通信协议以支持各层级间的数据传输。它为支撑层提供了原始的计算能力和数据存取接口，是整个系统稳定运行的物理基石。

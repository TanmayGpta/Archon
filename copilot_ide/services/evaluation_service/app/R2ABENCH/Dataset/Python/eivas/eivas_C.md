# 系统介绍

本项目是一个面向流行病学调查场景的 Web 应用程序，旨在通过格式化的数据录入、存储以及可视化的关联展示，为流调填报和开发人员提供全方位的决策辅助。该系统的核心价值在于将传统流调中繁琐的纸质记录转化为结构化、多维度的数字资产，从而解决人力消耗大、信息展示不直观以及海量数据下传播链分析困难等核心痛点。其目标用户主要包括负责一线现场问询与信息录入的流调填报人员，以及需要根据样本推断传染源和传播链的专业流调分析人员，通过技术手段提升防疫工作的准确性与效率。

# 核心目标

* 实现流调信息的格式化录入与存储，降低人工记录的冗余与疏漏。
* 提供可视化结构信息展示，辅助流调人员直观掌握病例的时空路径。
* 自动化梳理病例间的关联关系，提高传播链分析的效率与准确性。
* 汇总疫情统计数据，辅助决策者总结传染特征并制定防控策略。
* 节约流调过程中的时间成本与人力资源消耗。

# 功能特性

### 流调填报模块

* **信息录入**：当流调填报人员进行现场问询时，填报人员通过格式化接口录入病例基本信息、病情信息、行程轨迹及境外输入信息。
* **提示触发**：当病例无法回忆高风险地区详细活动时，填报人员通过系统搜索并触发已记录病例的地点提示。
* **路径验证**：当病例陈述不精确的地点名称时，填报人员通过系统选择地址并在地图上进行可视化确认。

### 病例管理模块

* **信息完善**：当病例信息需要补充或更正时，流调人员通过系统对已有条目进行编辑修改。
* **信息检索**：当流调人员需要查看整体进度时，系统通过列表形式展示所有病例的流调完成度。
* **筛选排序**：当分析人员寻找特定人群时，系统根据姓名、年龄排序或性别筛选条件对病例列表进行重排。

### 个案分析模块

* **路径查询**：当分析人员需要研判涉疫路径时，系统在地图上完整展示病例指定日期的活动轨迹。
* **关联分析**：当分析人员设定时空阈值后，系统自动检索并列出符合条件的关联病例信息条目。
* **关系图谱**：当分析人员需要确定密接者时，系统以图的形式展示具有地点共现关系的病例人物关系图。

### 整体分析模块

* **风险判定**：当用户查看地区风险界面时，算法模块根据病例经停信息计算并绘制地域流通图。
* **聚集分析**：当用户查看聚集性疫情部分时，算法模块根据路径相近程度将病例进行聚合展示。

### 疫情总览模块

* **多维统计**：当分析人员总结传染特征时，系统通过热力图展示空间分布、折线图展示温湿度走势、饼状图展示年龄/职业分布、柱状图展示交通频次。

# 技术限制

根据文档，该项目的硬性技术约束如下：

1. **后端框架**：使用 Django 开发框架。
2. **数据库**：使用 Neo4j 以及 MongoDB。
3. **编程语言**：项目使用Python语言进行后端编程。

# 非功能性需求

1. **处理时效**：系统需具备高并发处理能力，支持100名用户同时请求，且页面响应时间应小于1秒。 
2. **安全性 (Security)**：必须对涉及个人隐私的查询请求进行加密，并对异常高频访问的 IP 执行冷却限制，防止数据泄露与资源占用。 
3. **可用性 (Availability)**：系统需保持长时间稳定运行，并具备快速容灾能力，意外情况下需在20分钟内完成备用服务器切换。 
4. **灵活性 (Flexibility)**：代码架构需具备良好的可维护性，支持后期 Bug 修复、功能修改及新功能的扩展。 
5. **可移植性 (Portability)**：系统需具备跨平台运行能力，确保在不同操作系统和主流浏览器上的表现一致。 
6. **易用性与健壮性**：系统需提供大量操作提示以适配基层人员，且具备健壮的异常处理能力，不因错误输入而崩溃。 

# 系统架构描述

### 1. 应用层 (Application Layer)

应用层直接面向流调填报与分析人员，负责处理具体的**传染病流调业务场景**。该层通过对底层服务的编排，实现了流调表单的格式化录入（R1）、基于时空阈值的病例关联匹配（R10）以及针对聚集性疫情的聚合分析。它将复杂的流行病学逻辑（如境外输入处理、行程轨迹可视化、传播链推断）转化为直观的用户交互，并确保在多用户并发请求下维持亚秒级的业务响应。

### 2. 支撑层 (Support Layer)

* **数据预处理与算法驱动**：该层负责对流调文本进行格式化转换，并运行核心算法模型（如风险等级计算、病例聚合算法等），为应用层提供计算后的结果集。
* **查询与提示引擎**：提供基于历史数据的关联提示（R2）和多维度的筛选排序服务（R6-R8），屏蔽了原始数据的复杂检索逻辑。
* **安全与稳定性控制**：统一处理个人私密信息的加密传输、高频访问的IP冷却限制，以及系统在故障时的快速切换调度。

### 3. 基础层 (Infrastructure Layer)

基础层提供**通用的计算与存储能力**，与具体的流调业务无关。该层主要负责大规模格式化病例数据的持久化存储，并提供跨平台、跨浏览器的环境兼容性支持。它保障了系统在底层通信、Web分发以及计算资源分配上的可靠性，确保应用在连续运行环境下具备足够的健壮性，为上层的所有逻辑执行提供物理与基础软件支撑。

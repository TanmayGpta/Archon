 # 系统介绍

“智研通界”学术成果分享平台是一套面向广大科研人员和学者的资源共享与管理系统。该程序旨在解决现有学术平台“重查询、轻管理、弱交流”的核心痛点，在提供亿级中英文文献检索的基础上，特别强化了学者个人门户管理、学术成果认领、多层级机构管理以及站内社交功能 。系统通过建立学者与机构的双向验证机制，确保学术成果归属的准确性，并通过引入智能语义容错引擎、多轮对话搜索以及防信息茧房推荐机制，为高等院校、科研院所及企业科研人员提供一个集成果保护、资源共享与深度学术交流于一体的专业化协作环境 。

# 核心目标

* **学术成果分类与归属管理**：依据国际标准构建成果管理体系，通过学者认领与机构归属的双向验证机制确保成果归属准确 。

* **自动化数据采集与更新**：利用爬虫与API接口定期从公开数据库采集学者档案、论文等基础数据，并执行标准化清洗与增量同步 。

* **精细化访问与权限控制**：为游客、注册用户、认证学者提供差异化功能权限，并对敏感信息实施延迟公开或授权访问策略 。

* **深度互动与社交促进**：建立站内私信、评论、提问及争议处理机制，通过协作批注与分析报告分享提升学术互动效率 。

* **智能化检索与展示优化**：实现跨语言语义检索，通过个性化用户画像（演绎/归纳/视觉型）提供差异化的文献呈现形式，并预防学术信息茧房 。

# 功能特性

### 个人门户模块

* 当游客输入有效的用户名、密码及个人资料并点击提交时，系统进行新用户账户创建及保存 。

* 当已登录的普通用户提交相关验证信息申请认证时，系统将该申请提交给管理员审核以开启学者权限 。

* 当学者需要更新其职业信息时，学者进行昵称、邮箱、所属单位等个人档案信息的编辑与更新 。

### 文献检索模块

* 当用户输入自然语言或关键字并触发搜索时，系统通过语义容错引擎解析意图并展示多语种检索结果 。

* 当用户在结果页选择特定排序因子（如可信度、引用量）时，系统根据学术信用评分模型重新计算并刷新文献优先级 。

* 当用户连续搜索同领域学者触发多样性防御规则时，系统自动在结果中推荐跨学科的高潜力研究者 。

### 用户交流模块

* 当用户在文献详情页输入内容并点击发表时，普通用户或学者进行学术评论或向作者提问 。

* 当用户需要建立点对点联系时，系统在双方通过双向身份认证后进行私信发送 。

### 学术与机构管理模块

* 当学者发现系统中存在属于本人的论文时，学者进行学术成果的认领动作 。

* 当用户申请加入或创建研究机构时，机构管理员或系统管理员进行审核并管理机构树状结构 。

# 技术限制

1. **移动端平台**：文档中**未明确提及**具体的移动端操作系统（iOS/Android）硬性要求，仅在运行环境部分说明需支持常规操作系统的浏览器 。

2. **后端框架**：使用 **Django 4.2 LTS** 。

3. **数据库**：使用 **MySQL 8.0**（文档提及采用 MySQL 8.0 集群架构，每日全量备份 + 每小时增量备份）。

4. **编程语言**：前端使用 **Vue 3.3** 进行开发（对应 JavaScript/TypeScript），后端基于 Django（对应 **Python**）。

# 非功能需求

* **处理时效**：
    * **响应性能**：用户修改筛选条件后，结果列表需在 **500ms** 内完成更新 。

    * **更新频率**：学术成果数据库需具备每日同步的增量更新机制 。

* **安全性 (Security)**：
    * **数据保护**：用户密码必须采用哈希加密方式存储 。

    * **权限治理**：未公开成果需经机构管理员授权方可查看；敏感信息（如影响力排名）需实施3个月的延迟公开策略 。

* **可用性 (Availability)**：
    * **数据可靠性**：系统需具备完善的备份机制（每日全量+每小时增量），保留周期为30天。

    * **争议处理**：设有三级争议处理机制（系统初审、专家复审、管理终审）以维护社区秩序 。

* **灵活性 (Flexibility/Scalability)**：
    * **架构扩展**：支持多层级学术领域分类及高校/院所/实验室三级机构关系树的动态构建 。

    * **存储灵活性**：系统需支持关系型与非结构化混合存储，以应对亿级中英文文献条目 。

* **可移植性 (Portability)**：
    * **跨平台/浏览器**：系统应兼容 Chrome、Edge、Firefox 等主流浏览器内核 。

    * **语种兼容**：系统设计需考虑到多语种（中/英/日/德）文献之间的兼容性与互译支持 。

# 系统架构描述

### **1. 应用层 (Application Layer)**
应用层直接面向最终用户（游客、普通用户、学者及管理员），负责处理特定的学术业务场景与交互逻辑 。该层通过高度内聚的业务模块（如个人门户、文献检索、用户交流等）封装原生细节，实现了复杂的业务流转，包括学者身份的双向认证机制、多轮对话式高级检索以及学术成果的认领与申诉处理 。它通过调用支撑层提供的通用服务，完成用户请求的响应与页面状态的实时更新 。

### **2. 支撑层 (Support Layer)**
支撑层为应用层提供了一套内聚的学术通用服务集合，起到核心桥接作用 。其功能涵盖了：

* **语义与画像服务：** 通过语义容错引擎、学术概念图谱及用户画像引擎，支撑跨语言术语映射、意图纠错及个性化内容推荐 。

* **安全与规范服务：** 提供基于哈希加密的身份验证、基于业务规则的权限控制（如延迟公开策略）以及学术不端检测机制（如草稿查重与黑名单过滤） 。

* **数据清洗与分析：** 负责采集数据的标准化清洗、去重及结构化处理，并定期生成热点分析报告和影响力画像 。

### **3. 基础层 (Infrastructure Layer)**
基础层是系统的底层计算与分发保障，与具体的学术业务逻辑解耦 。它基于 Linux/Windows 等操作系统及 MySQL 8.0 集群架构构建，负责亿级文献条目与用户行为日志的持久化混合存储 。同时，该层提供了网络爬虫与 API 接口，用于从公开数据库获取原始学术数据，并支持跨浏览器内核的稳定运行及每日全量/增量的数据备份，确保系统的高可靠性与响应性能 。

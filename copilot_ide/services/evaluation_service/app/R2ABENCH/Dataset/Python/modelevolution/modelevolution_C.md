# 系统介绍

模型演化版本管理可视化工具是一款专为机器学习领域设计的教育与管理应用程序，旨在通过可视化的手段展示复杂机器学习模型的架构、性能及其演化关系 。随着人工智能的快速发展，初学者往往难以在众多模型中找到学习起点，也难以理解模型间的迭代与借鉴关系，该项目正是为了解决这一核心痛点，为学习者提供直观的学习指导，同时为研究人员和贡献者提供模型版本管理与协作的平台 。

# 核心目标

* **可视化呈现**：通过拓扑图等形式直观展示多个机器学习模型之间的演化关系和具体演化细节 。

* **辅助教育学习**：为初学者提供有效的学习路径，帮助其快速了解模型结构、源码及性能指标 。

* **模型版本管理**：实现对机器学习模型（如ONNX、PyTorch源码）的上传、在线编辑、修改及删除等全生命周期管理 。

* **演化关系定义**：支持贡献者自主定义、增加或删除模型间的演化逻辑，包括算子的增删与参数调整 。

* **权限与安全管控**：建立完善的用户角色体系（学习者、贡献者、管理员），确保数据的安全存储与权限的合规变动 。

# 功能特性

### 1. 账号与权限模块

* 当用户需要进入系统执行操作时，用户进行注册、登录或注销动作 。

* 当用户忘记密码或需要提升权限时，用户进行修改密码或发起权限变动申请动作 。

* 当管理员收到申请或需要维护秩序时，管理员进行用户管理、删除用户或权限变动审核动作 。

### 2. 模型浏览与搜索模块

* 当用户寻找特定模型时，学习者进行关键词搜索动作 。

* 当用户选中某个模型时，学习者进行查看模型基本信息、演化图及演化细节动作 。

### 3. 模型贡献与编辑模块

* 当贡献者有新数据分享时，贡献者进行上传ONNX文件或PyTorch源码动作 。

* 当发现模型信息有误或需优化时，贡献者进行在线编辑代码、修改模型简介或删除模型动作 。

### 4. 演化关系定义模块

* 当存在新旧模型迭代关系时，贡献者进行增加或删除模型演化关系动作 。

* 当需要描述具体的结构变化（如复用某一层）时，贡献者进行修改模型演化细节动作 。

# 技术限制

1. **移动端平台**：网页界面需根据智能手机和平板电脑等设备环境进行调整 ，支持在多种移动端浏览器上运行。

2. **后端框架**：使用 **Django** 开发框架 。

3. **数据库**：采用 **Neo4j**（用于存储演化关系图）和 **MySQL** 存储技术 。

4. **编程语言**：主要使用 **Python**（类库支持）和用于前端开发的 **React** (JavaScript/TypeScript) 。

# 非功能需求

* **处理时效**：静态页面响应时间需低于1秒；从添加模型到产出结果的时间不得超过1分钟 。

* **安全性 (Security)**：采用 OAuth 2.0 双因素身份验证；敏感数据传输与存储需经过 TLS 加密；数据库中的模型使用 AES/DES 对称加密 。

* **可用性 (Availability)**：系统需支持 7*24 小时运行，年非计划停机时间少于 30 小时；故障时需在 0.5 小时内切换至备用机，且保证多管理员同时修改时数据不冲突 。

* **灵活性 (Flexibility/Scalability)**：要求代码结构与表现分离（HTML与CSS分离），模块化书写以保证易于定位故障和增强功能 。

* **可移植性 (Portability)**：系统采用 B/S 架构，需兼容 Windows、macOS、Linux 等操作系统，并适配 Chrome、Firefox、360 等主流浏览器及各种屏幕尺寸的移动设备 。

# 系统架构描述

该系统采用 **B/S（浏览器-服务器）分层架构**，通过明确的职责内聚划分，构建了从底层数据支撑到高层业务场景的完整虚拟机器体系 ：

### 1. **应用层 (Application Layer)**

作为最高层级，直接面向“学习者”、“贡献者”和“管理员”三类用户角色，聚焦于机器学习模型的可视化业务场景 。该层通过 React 框架构建高度交互的虚拟界面，实现模型架构的拓扑展示、演化关系的动态演变以及模型源码的在线编辑功能 。它封装了具体的业务流程逻辑，如权限变更审核流程、模型上传与演化细节定义，确保业务逻辑与底层实现细节解耦 。

### 2. **支撑层 (Support Layer)**

该层基于 Django 框架提供内聚的通用服务集合，起到了核心的桥接作用 。它通过 RESTful 接口或类似机制响应前端请求，承担了身份验证（如 OAuth 2.0 双因素认证）、数据加密处理（TLS、AES/DES 加密）以及复杂模型演化逻辑的解析与计算职责 。此外，该层利用 Python 类库实现对 ONNX 和 PyTorch 模型的处理，将原始模型数据转化为应用层可识别的演化拓扑结构 。

### 3. **基础层 (Infrastructure Layer)**

处于架构的最低层级，由计算、存储和通信协议构成，与具体应用业务无关。在存储维度，系统通过 **Neo4j 图数据库** 处理复杂的模型拓扑演化关系，辅以 **MySQL 关系型数据库** 存储用户信息与基础属性，形成异构存储支撑 。在通信维度，该层依赖 HTTP/HTTPS、TCP/IP 等标准协议保障数据的可靠传输，并基于跨平台的操作系统环境（Windows/Linux/macOS）提供基础的计算与 IO 分发机制 。

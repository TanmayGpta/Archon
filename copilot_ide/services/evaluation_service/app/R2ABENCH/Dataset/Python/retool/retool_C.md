# 系统介绍

ReTool 是一款面向持续演化的软件需求管理工具。在软件开发过程中，由于需求往往难以在前期完全确定并处于动态变化中，该程序旨在解决市面上流行工具在需求导入与分析自动化程度低、功能繁杂及学习成本高带来的痛点。项目通过集成需求条目化、结构化、冲突检测、关联关系分析及共性需求识别等先进算法，实现了从需求文本自动提取清晰条目并预判变更影响的核心价值。其目标用户涵盖了需要频繁进行需求变更与管理的管理人员（如项目经理、组长），以及需要根据精确需求进行开发与测试的项目组普通成员，同时包括负责系统维护的管理员。

# 核心目标

* **自动化需求处理**：通过算法自动化地从导入的 Word 或文本中获取清晰的需求条目并实现结构化。
* **智能需求分析**：实现需求间的冲突检测、共性识别以及关联关系分析，以提前预判需求变更带来的影响。
* **全生命周期追踪**：建立从需求到设计模块及测试用例的正向追踪机制，辅助面向变更的开发与测试工作。
* **高效项目与人员管理**：提供多层级的用户权限管理与灵活的项目配置功能，支持跨项目的角色定义。
* **提升演化效率**：通过降低人工干预和学习成本，加速软件项目在持续演化过程中的迭代进程。

# 功能特性

### 用户管理模块

* 当用户访问注册界面并填写信息时，用户进行账号注册动作。
* 当用户输入正确的凭据时，系统用户进行登录动作以获取项目访问权限。
* 当系统管理员需要维护人员名单时，系统管理员进行添加、删除用户或修改用户角色的动作。
* 当用户忘记密码时，系统管理员进行重置用户密码的动作。

### 项目管理模块

* 当新业务启动时，项目经理进行创建项目并设置项目基线节点的动作。
* 当项目人员变动时，项目经理或项目组长进行添加或删除项目成员、修改项目角色的动作。
* 当项目信息需要更新时，有权限的用户进行修改项目信息或查看项目列表的动作。

### 需求管理模块

* 当用户上传需求文件时，需求管理模块进行从 Word 导入需求条目及自动化条目化的动作。
* 当需求发生演化时，项目经理或组长进行创建、修改、删除或移动需求条目位置的动作。
* 当进行影响分析时，算法服务进行需求冲突检测、共性识别及关联关系分析的动作。
* 当需要追踪开发进度时，用户进行建立需求正向追踪（至设计或测试）的动作。

# 技术限制

1. **移动端平台**：前端采用 Vue.js 框架构建网页界面。
2. **后端框架**：服务端采用微服务架构，使用了基于 Python 的 **Flask** 轻量级 Web 框架。
3. **数据库**：使用面向文档的 **MongoDB** 数据库（NoSQL）作为数据存储。
4. **编程语言**：主要使用 **Python**（用于后端 Flask 及机器学习库 PyTorch、NLP 处理）。

# 非功能性需求

* **处理时效（响应时间）**：系统需限制同一时刻的访问量以保证稳定，超出峰值时系统会对用户进程进行阻塞等待，直至资源可用。
* **安全性 (Security)**：
* **访问控制**：系统严格区分系统角色（管理员、普通用户）与项目角色（经理、组长、成员），根据角色分配增删改查权限。
* **数据保护**：用户必须登录后才能使用系统，数据库负责成功保存及保护用户凭据。
* **可用性 (Availability)**：系统运行依赖网络连接，若无法连接则所有需求无法实现；同时对高负载的算法服务建议运行在高性能服务器上以保证可用性。
* **灵活性 (Flexibility/Scalability)**：服务端采用微服务架构，各子服务独立开发、部署和升级，具有很高的灵活性和扩展性。
* **可移植性 (Portability)**：前端使用轻量级的 Vue.js 框架，界面设计需考虑自适应屏幕尺寸以及在不同操作系统下的呈现效果。

# 系统架构描述

本系统采用了典型的**前后端分离**与**微服务化**的分层架构模式，通过不同层次间的协作完成从用户交互到复杂需求分析的业务闭环：

### 1. **应用层 (Application Layer)** 

该层作为系统的最顶层，直接面向最终用户（如项目经理、系统管理员等）。它基于 **Vue.js 框架**构建了一套轻量级的网页交互界面，负责呈现业务逻辑的最终结果。应用层通过接收用户的操作指令（如需求导入、冲突检测请求），将其转化为标准化的服务调用，传递给下层处理。其核心职责在于业务场景的感知与展示，而不涉及底层数据的直接存储或算法的具体实现。

### 2. **支撑层 (Support Layer)** 
该层通过**微服务架构**（由 Flask 框架实现）提供了一系列内聚的通用服务集合。
* **服务治理与调度**：通过网关与各业务微服务（用户管理、项目管理、需求管理服务）协同，完成业务逻辑的编排与分发。
* **领域能力抽象**：集成并封装了高性能的**算法服务**（涉及 NLP、PyTorch 及 Word2vec 模型），将复杂的“需求条目化”、“冲突检测”和“共性识别”等计算逻辑抽象为可调用的接口，屏蔽了算法实现的细节与硬件性能依赖。

### 3. **基础层 (Infrastructure Layer)** 
作为系统的底层基座，该层通过 **MongoDB 数据库**提供面向文档的非关系型数据存储机制，负责处理所有业务对象（如用户信息、项目基线、需求条目树）的持久化与增删改查操作。基础层与上层的“处理逻辑”解耦，通过标准的数据交互协议响应支撑层的指令，确保系统数据的完整性与一致性。

# 系统介绍

MyTorch 是一款面向神经网络初学者及非专业开发者的可视化深度学习框架系统 。该应用程序基于轻量级的 NNEngine 框架进行增强开发，集成了模型配置、数据加载、模型训练及任务推理等核心功能，旨在解决主流深度学习框架（如 TensorFlow、PyTorch）因功能过于复杂、学习曲线陡峭以及对计算资源要求过高而导致初学者难以快速上手和理解核心原理的痛点 。系统通过提供直观的可视化界面和自动化的资源管理（如 GPU 加速 API），使用户无需编写复杂代码即可完成从模型搭建到推理部署的全流程，从而为深度学习学习者提供一个简单、易用且功能齐全的实践平台 。

# 核心目标

* **功能增强与扩展**：在原有轻量级框架基础上，引入更多模型权重初始化方法、经典模型结构（如 ResNet、VGG、Transformer）及内置数据集（如 ImageNet、COCO），提升框架的灵活性和应用范围 。

* **计算性能优化**：实现 GPU 加速功能，通过并行计算提升处理计算密集型任务的效率，缩短大型模型和数据集的训练时间 。

* **低门槛可视化操作**：开发直观的前端界面（包括配置、训练、推理界面），使用户能通过图形化操作而非编写代码来管理模型和参数 。

* **全流程闭环管理**：通过系统后端与数据库的联动，实现模型初始化、训练日志记录、推理历史存储及模型管理的持久化，保障系统的稳定性和可追溯性 。

* **教学与原理普及**：通过实时反馈和训练过程的可视化展示（如损失下降曲线、准确率变化），帮助初学者直观理解神经网络的构建与优化过程 。

# 功能特性

### 1. 模型配置模块

* 当用户选择**定义新模型**时，**前端系统**提供内置模块供用户通过图形化方式搭建模型结构 。

* 当用户完成**模型结构调整**时，**系统**自动配置并关联相应的损失函数 。

* 当**模型配置成功**时，**后端模块**将配置好的模型信息存储至数据库并向用户发送成功通知 。

### 2. 加载数据模块

* 当用户需要**准备训练数据**时，**用户**可选择系统预设的内置数据集（如 CIFAR-10, SVHN 等）或自定义数据 。

* 当用户**定义数据载入方式**时，**系统**允许用户配置数据预处理方法、数据增强策略以及数据集划分比例 。

### 3. 模型训练模块

* 当用户**启动模型训练**前，**用户**通过配置界面定义超参数（如批次大小、学习率）、优化器类型及训练停止条件 。

* 当用户**执行训练指令**时，**系统**允许用户指定计算模式（使用 CPU 或利用 GPU 加速） 。

* 当**训练任务运行**时，**系统**实时向前端推送损失值和精度等评估结果，并根据配置自动保存当前最优模型 。

* 当发生**梯度爆炸等异常**时，**系统故障处理机制**会自动中止训练以避免模型崩溃 。

### 4. 模型推理模块

* 当用户选择**图片分类任务**时，**用户**上传单张图像，**系统**通过调用模型 forward() 方法返回预测结果 。

* 当用户执行**模型性能测试**时，**推理器**加载指定地址的模型并与测试集匹配，最后在界面上展示整体评价指标 。

# 技术限制

1. **移动端平台**：运行环境为支持 Python 环境的计算机设备 。

2. **后端框架**：基于原有的小型深度学习框架 **NNEngine** 进行增强与二次开发 。

3. **数据库**：使用 **SQLite** 实现本地持久化存储，并具备自动备份机制 。

4. **编程语言**：系统实现采用 **Python 3.8.x** 及以上版本 。

5. **硬件约束**：GPU 加速功能要求配备支持 **CUDA**（且计算能力 > 3.0）的 **NVIDIA GPU** 。

# 非功能需求

* **处理时效**：界面对用户指令的平均响应时间应小于 0.75s，训练引擎对指令的平均响应时间应小于 2.5s 。

* **安全性 (Security)**：系统需具备必要的安全性和隐私保护机制，防止潜在漏洞攻击，并确保用户模型与数据的机密性和完整性 。

* **可用性 (Availability)**：系统需具备运行时异常监控（如内存溢出监控），并在硬件故障或数据库异常时，支持通过自动备份文件进行手动或自动的数据恢复 。

* **灵活性 (Flexibility/Scalability)**：系统应支持用户对模型和数据集的自定义拓展；GPU 加速功能需通过易用的 API 实现，确保与原框架高度兼容以便未来扩展 。

# 系统架构描述

MyTorch 系统采用清晰的纵向分层架构，通过层间协作实现深度学习任务的端到端支撑。

### 1. **应用层 (Application Layer)**

该层直接面向终端用户（主要是深度学习初学者），通过**可视化前端界面**提供业务逻辑封装 。它负责处理具体的业务场景，包括模型结构的图形化配置、训练超参数的交互式设定、数据集的路径映射以及推理任务的触发 。此层将复杂的神经网络构建过程抽象为直观的操作流，独立于具体的底层计算细节，关注用户意图的达成与结果的实时反馈可视化。

### 2. **支撑层 (Support Layer)**

该层发挥核心桥接与通用服务集成作用。它主要由**系统后端服务**和**数据持久化模块**组成 。支撑层通过标准化的 API 接口响应应用层的请求，调度下层的计算资源完成模型初始化、训练迭代及推理计算 。同时，该层提供了内聚的通用支撑服务，如基于 SQLite 的训练/推理日志持久化、数据集载入器的预处理管理以及模型权重的初始化策略，为应用层屏蔽了底层框架的调用复杂性。

### 3. **基础层 (Infrastructure Layer)**

该层是系统的底层引擎（NNEngine 扩展版），基于基础的**计算、通信与分发机制**构建。它不仅包含了神经网络的前向/反向传播逻辑，还通过集成的 **GPU 加速模块**（如 CUDA 并行计算函数）直接与硬件资源交互，以提供高效的矩阵运算支持。基础层预内置了经典模型结构（如 ResNet, Transformer）和标准数据集接口，作为与具体业务场景无关的原子能力，为整个系统提供最底层的算力支撑与数据分发保障 。
